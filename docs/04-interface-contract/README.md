# AI Cinematic Studio 接口契约基础

## 1. 目的与范围

本目录建立 AI Cinematic Studio V2.3 相邻层之间的接口契约基础，使未来接口在实现前具备一致的方向、描述字段、关联标识、事件信封和错误语义。

这些文档只定义技术无关的契约规则，不批准任何端点、协议、序列化格式、服务、业务字段、数据库结构或运行时实现。目录中的模板也不代表具体接口已经存在。

## 2. 调用方向

允许进入评审的相邻层调用方向为：

```text
Application Layer
        ↓
V5 Core OS
        ↓
V4 Platform
        ↓
V3 Render Core
        ↓
Compute
```

箭头表示上层可以在具体契约获批后调用相邻下层的公开接口，不表示具体调用已经实现，也不限定响应、数据或事件的传递方式。下层不得反向依赖上层；跨层、循环和私有实现直连继续由 [层级依赖图](../../architecture/dependency-map.md) 禁止。

Foundation 不属于 ACS-P0-003 的层间接口契约范围，既有 V2.3 架构关系保持不变。

## 4. 每个接口的必填说明

任何具体接口进入评审前，必须完整说明以下五项；缺少任一项时，接口仍处于未定义状态：

| 字段 | 必须回答的问题 |
| --- | --- |
| Purpose | 接口解决什么问题、适用边界是什么、明确不负责什么？ |
| Input | 输入的逻辑含义、必填/条件字段、约束和关联标识是什么？ |
| Output | 成功结果的逻辑含义、完成判据和兼容性承诺是什么？ |
| Error | 可能出现哪些稳定错误语义、由谁负责、调用方能否重试？ |
| Ownership | 哪一层拥有契约、谁批准变更、生产者和消费者各承担什么责任？ |

模板中的 Input 和 Output 只描述语义，不得借此选择传输协议、字段编码、语言类型或框架模型。

## 5. 统一关联标识

以下名称是跨层契约使用的统一逻辑标识。它们均为不透明标识；本阶段不规定生成算法、字符格式、长度、存储方式或传输编码。

| 标识 | 语义 | 传递规则 |
| --- | --- | --- |
| Request ID | 标识一次逻辑请求 | 在请求首次进入契约链时建立，并在同一次相邻层调用链中原样传递 |
| Trace ID | 关联一次端到端交互中的多个请求或事件 | 同一追踪范围内保持不变；一个 Trace ID 可以关联多个 Request ID |
| Project ID | 标识接口操作所属的项目上下文 | 仅在接口具有项目上下文时必填；不能单独作为授权证明 |
| Asset ID | 标识接口所引用的资产 | 仅在接口涉及资产时必填；不得编码资产位置、格式或业务状态 |
| Job ID | 标识接口所引用的工作单元 | 仅在接口涉及工作单元时必填；不据此定义任务状态机或执行技术 |

统一规则：

1. 不得在标识中嵌入需要调用方解析的业务语义。
2. 标识只能用于身份与关联，不能替代身份认证、权限校验或数据所有权判断。
3. 上层已经提供的 Request ID 和 Trace ID 不得由下层静默替换；缺失时的建立责任必须在具体契约中声明。
4. Project ID、Asset ID、Job ID 按接口语义条件使用，不得用无意义占位值伪造上下文。
5. 日志、错误和事件只引用必要标识，不得因此暴露敏感内容。

## 6. 接口声明骨架

具体接口记录至少采用以下结构：

```text
Contract Metadata
Purpose
Input
Output
Error
Ownership
Compatibility and Lifecycle
```

Contract Metadata 应记录契约标识、状态、版本、调用方、提供方、责任人和关联任务，但本阶段不规定这些字段的机器格式。

## 7. 兼容性与变更治理

- 已发布契约的语义必须稳定；调用方不得依赖未声明的内部行为。
- 新增必填输入、改变输出语义、改变错误含义或删除既有字段，均视为潜在不兼容变更。
- 改变层级方向、契约所有权、统一标识、事件信封或错误标准时，必须遵守 [架构变更流程](../../governance/ARCHITECTURE_CHANGE_PROCESS.md)。
- 废弃契约必须声明替代项、迁移窗口、验证条件和停止使用条件，不能静默删除。
- 具体协议绑定、版本协商方式和兼容性测试工具由后续获批任务决定。

## 8. Phase 0.3 非目标

本任务不创建 API 代码、服务实现、数据库、业务逻辑、接口端点、网络协议、消息中间件、框架依赖或 V5/V4/V3 内部模块。任何具体实现都必须等待后续任务授权。
