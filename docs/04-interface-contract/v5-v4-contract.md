# V5 Core OS → V4 Platform Contract Template

> 状态：技术无关的层间契约模板；不代表具体接口或实现已经获批。

## Purpose

本模板用于记录 V5 Core OS 调用 V4 Platform 公开能力时必须明确的契约信息。唯一允许的相邻调用方向是：

`V5 Core OS → V4 Platform`

该方向属于标准高层调用链 `Application Layer → V5 Core OS → V4 Platform → V3 Render Core → Compute`。响应或错误沿调用上下文返回不构成 V4 Platform 对 V5 Core OS 的反向调用，也不授权 V4 Platform 依赖 V5 Core OS。

填写本模板时应说明契约目标、调用前提、成功判定和明确非目标，但不得在此定义端点、传输协议、序列化格式、业务字段、数据库结构或实现技术。本模板只约束边界，不新增、拆分或改变 V2.3 模块。

## Input

正式契约应记录以下输入约束，但本模板不预设其表示形式：

- 调用意图及其授权来源；
- 调用方必须满足的前置条件；
- V4 Platform 可以验证的边界条件；
- 本次交互适用的关联标识符及其来源；
- 不适用或尚未建立的标识符及原因。

V5 Core OS 只可向 V4 Platform 的公开契约提交输入，不得传递对自身内部实现的引用，也不得借此直接触达 V3 Render Core 或 Compute。

## Output

正式契约应记录可观察的成功结果、完成条件以及调用方可以依赖的稳定语义，不得把 V4 Platform 的内部表示作为公开输出。

输出必须保留适用的关联上下文。若某个 Asset ID 或 Job ID 在处理过程中首次被权威建立，正式契约应说明由哪个边界负责返回该身份；本模板不指定该身份由何种模块建立，也不定义其格式或载体。

## Error

正式契约应按照 [错误码标准](error-code-standard.md) 记录失败语义、责任边界、是否允许重试、部分完成状态和调用方可采取的动作，但不得在本模板中预设具体错误码、异常类型或协议映射。

错误结果必须保留与原调用相同的适用 Request ID、Trace ID、Project ID、Asset ID 与 Job ID 上下文。错误处理不得触发反向依赖、跨层补偿调用或对另一层内部状态的直接修改。

## Ownership

- V5 Core OS 负责遵守公开契约、提供有效调用上下文并正确处理结果与错误。
- V4 Platform 负责其公开契约的语义、兼容性、边界验证和内部实现封装。
- 双方共同负责契约变更评审、兼容性证据和标识符传播验证。
- 具体团队、人员、服务或模块所有者必须在契约实例获批时填写；本模板不预先指定。

## Identifier Applicability and Propagation

统一标识的规范语义以本目录 [README](README.md#5-统一关联标识) 为唯一基础；下表只说明该相邻边界的适用性与传播责任。

| 标识符 | 适用性 | 传递要求 |
| --- | --- | --- |
| Request ID | 当交互属于一次可关联请求时适用；进入受治理调用链的首个边界应确保请求身份已经建立 | 后续相邻层沿同一请求语义传递，不得静默替换或改作其他用途 |
| Trace ID | 当追踪上下文存在或交互纳入追踪时适用；它与 Request ID 含义不同，二者不得互相推导或替代 | 在适用调用链中保持同一追踪关联语义，具体追踪表示方式由后续获批契约决定 |
| Project ID | 当交互明确归属于一个已识别项目时适用 | 沿涉及该项目的相邻调用传递；不适用时不得使用虚构值占位 |
| Asset ID | 当交互目标、输入或已建立结果关联到已识别资产时适用；资产身份尚未建立时可以不适用 | 已存在时保持身份语义不变；首次建立后由正式契约规定的责任边界返回并继续传递 |
| Job ID | 当交互属于或产生一个已识别作业上下文时适用；作业身份尚未建立时可以不适用 | 已存在时沿作业相关相邻调用传递；首次建立后由正式契约规定的责任边界返回并继续传递 |

统一规则：

1. 标识符只用于关联和上下文连续性，其存在不授予身份认证、授权或资源访问权。
2. 调用方传递所有已存在且适用的标识符；接收方不得无依据地改写、合并、复用或推断缺失标识符。
3. 接收方在输出和错误上下文中保留适用标识符，使一次交互能够被端到端关联。
4. 不适用的标识符应保持不适用，不得使用空含义、固定值或其他标识符冒充。
5. 本模板不定义标识符的格式、长度、生成算法、基数、字段名称、传输位置或持久化方式。

## Change Control

契约实例必须关联获批任务并完成相邻两层共同评审。任何反向、跨层或循环调用提案均不能通过修改本模板获得授权；应按 [架构变更流程](../../governance/ARCHITECTURE_CHANGE_PROCESS.md) 独立评审。若变更会改变 V2.3 模块职责或层级方向，必须先完成架构基线变更审批。
