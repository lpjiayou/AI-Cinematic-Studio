# 数据存储抽象

## 1. 文档定位

本文定义 AI Cinematic Studio V2.3 数据架构中的四类逻辑存储能力：Operational Storage、Object Storage、Vector Storage、Analytics Storage。它们用于描述数据需要何种能力，不代表已经选择数据库、产品、服务、部署模式或数据访问技术。

本文不创建存储实现，不定义 SQL Schema、表、字段、索引、查询、接口、容量参数或业务实体，也不改变数据所有权和 V2.3 层级职责。

七个数据分类与四类存储能力是彼此独立的治理维度。本文不建立 Identity、Project、Asset、Production、Render、Business、Intelligence 到任何存储能力的默认映射。

## 2. 抽象原则

1. **能力与产品分离**：先描述语义、生命周期、一致性和访问需要，再由后续获批选型决定实现。
2. **存储不等于所有者**：物理保存某份数据的系统不会因此获得其权威语义或变更权。
3. **权威与派生分离**：每份副本必须声明是权威数据、受控副本、缓存、索引还是分析派生。
4. **位置不进入标识**：Project ID、Asset ID、Job ID 等逻辑标识不得编码存储类型、位置、分区或供应商信息。
5. **跨边界只走契约**：任何存储能力都不能作为绕过层间接口、共享内部状态或建立反向依赖的通道。
6. **可替换与可退出**：技术绑定必须说明迁移、验证、回滚和退出条件，抽象语义不依赖某项实现才能成立。

## 3. Operational Storage

### 逻辑目的

支持当前运行上下文中需要被读取、验证和受控变更的数据。只有在所有权记录明确指定时，其中的数据才可视为权威状态。

### 必须声明

- 数据分类与权威所有者；
- 允许执行状态变更的契约边界；
- 适用的一致性、不变量、版本和冲突处理规则；
- 生命周期、保留、恢复和审计要求；
- 与任何 Object、Vector 或 Analytics 派生数据的关系。

“Operational”不意味着关系型、文档型、键值型或任何具体数据模型。

## 4. Object Storage

### 逻辑目的

承载大体量、不透明或内容型对象，以及需要独立版本、校验和保留治理的对象表示。Object Storage 中的内容与 Asset 的权威身份、描述和生命周期是不同关注点。

### 必须声明

- 对象与权威 Asset ID 或其他治理标识的关联方式；
- 对象版本、完整性、可用性和替换语义；
- 所有权、访问、保留、归档和受控处置责任；
- 内容丢失、重复或不可读时的验证与恢复要求。

对象路径、地址或名称不得替代 Asset ID，也不得被上层作为稳定业务契约。

## 5. Vector Storage

### 逻辑目的

承载从权威或已批准来源派生的向量表达，以支持未来获批的相似性、检索或智能分析需求。向量表达默认是派生数据，不能替代其来源事实。

### 必须声明

- 权威来源、来源版本和生成上下文；
- 派生结果的适用范围、有效期和重建条件；
- 来源变化、删除、限制或纠正后的同步责任；
- 质量、漂移、访问和敏感性验证要求。

本文不选择向量生成方法、维度、距离语义、索引结构、检索算法或向量产品。

## 6. Analytics Storage

### 逻辑目的

承载用于分析的历史、汇总、快照或其他派生视图。分析结果必须能够说明来源范围和观测时间，不能反向覆盖权威运行数据。

### 必须声明

- 来源数据、来源所有者和转换责任；
- 数据所代表的观测时间、刷新边界和已知滞后；
- 汇总、纠正、重算、保留和处置规则；
- 消费限制、敏感性和对决策适用性的说明。

“Analytics”不意味着特定查询语言、仓库形态、湖形态、文件格式或商业智能产品。

## 7. 抽象能力之间的关系

以下关系是允许评审的通用模式，不表示具体数据流已经批准：

- 权威所有者可通过公开契约向 Object Storage 关联受控内容对象；
- 权威或获准来源可产生可重建的 Vector Storage 派生表达；
- 权威数据可经受控转换形成 Analytics Storage 视图；
- Operational Storage 可引用其他抽象能力中的受控对象，但不能通过内部位置形成隐式契约；
- 任何派生能力都不得绕过权威所有者直接接受外部事实修改。

实际数据流、同步方式和物理部署必须由独立任务与接口契约批准。

## 8. 一致性与生命周期责任

每项存储绑定必须声明：

- 哪一份数据是权威来源；
- 变更何时对哪些消费者可见；
- 如何识别版本、过期视图和冲突；
- 派生数据如何重建、核对和失效；
- 归档、保留、限制和处置如何传播；
- 失败时如何验证、恢复和审计。

统一规则见 [数据一致性规则](data-consistency-rules.md)，Asset 相关规则见 [Asset 生命周期](asset-lifecycle.md)。
数据分类依据 [数据域模型](data-domain-model.md)，权威责任依据 [数据所有权](data-ownership.md)；存储选择不得替代其中任何一项治理决定。

## 9. 技术绑定决策模板

未来将抽象能力绑定到实现技术时，至少记录：目的、数据分类、所有者、权威性、生命周期、一致性、安全与合规、可用性与恢复、迁移与退出、成本和可替换性。

正式选择必须使用 [技术栈选型记录模板](../../architecture/technology-stack-decision.md) 并遵守 [架构变更流程](../../governance/ARCHITECTURE_CHANGE_PROCESS.md)。本阶段不填写候选产品或推荐方案。
