# ADR-0010 — K2 Canonical Lineage Bootstrap After Missing Durable State

- Status: `ACCEPTED / G0 REMOTE-VERIFIED / G1 HOST-VERIFIED / CLOSED`
- Date: `2026-08-21`
- Decision owners: Project Lead / Architecture Owner `蔺鹏`
- Extends: `ADR-0009-k2-publishable-media-production.md`
- Contract: `architecture/K2_CANONICAL_LINEAGE_BOOTSTRAP_CONTRACT.md`

## Context

The K2 publishable-production wave assumed that the accepted local-evidence K2
lineage could be reopened and extended. A read-only location audit subsequently
covered `/data`, `/root`, `/home`, `/tmp` and 15 archives. It found no K2 Core
production database or `EpisodeProductionRun`. The only two SQLite candidates were
ComfyUI databases, and no archive contained a database member. The audit SHA-256 is
`7aaa36333f08be3bdfd09c6b4632804f3b7bf14a0bd1bc35f359df0391fa167b`.

Repository inspection also found no production snapshot/import path. Fixed-looking
K2 refs exist only inside in-memory or temporary-directory tests and cannot be
promoted into production lineage. Starting Creator against a default path would
silently create an empty database and would not recover the missing lineage.

On `2026-08-21`, the Project Lead explicitly authorized establishment of a new
canonical K2 lineage.

## Decision

1. The missing durable lineage is not recovered and must never be described as
   recovered. Historical G0→G7 and GPU runtime evidence remains historical technical
   evidence only.
2. One new K2-001 canonical root lineage may be initialized from the explicitly
   reviewed K2-001 bootstrap specification. The specification remains input to an
   authorized bootstrap; it is not itself a V5 domain fact.
3. Bootstrap is a one-time trusted Operator Application over existing V5 public
   boundaries. It may use the existing Core-only M5 EpisodePlanItemBinding operation,
   but it must not add an HTTP route, import test fixtures, call V4/V3/providers or
   execute application-authored SQL.
4. All refs are generated by accepted V5 ref factories and captured from returned
   records. Names, titles, episode numbers, document keys and test refs are never used
   as authoritative identity.
5. Bootstrap writes to a new same-filesystem staging directory. The canonical target
   must not already exist. Only after all writes, restart validation, read-only scan
   and receipt validation pass may the staging directory be atomically renamed to the
   canonical target.
6. The maximum authorized result is one durable root chain and one
   `EpisodeProductionRun` in `ROOTS_READY` with `publicationAllowed=false`.
7. This authorization does not create or approve M6 Authority, Identity Lock,
   RightsManifest, ProviderExecutionPolicy, budget authority, live media, selected
   AssetVersion, human master decisions or publication eligibility. All remain
   fail-closed.
8. The bootstrap emits a secret-free receipt containing stable refs, versions,
   payload/upstream digests, specification digest, repository revision and relative
   database inventory. It emits no creative payload, token, credential or absolute
   host path.
9. Creator may be started only after the canonical directory exists and the operator
   explicitly injects its lifecycle and episode-production database paths. Its
   authenticated public API must then return the exact receipt refs and digests.

## Required sequence

```text
governance checkpoint remote-verified
→ bootstrap specification validates without writes
→ explicit apply acknowledgement
→ same-filesystem staging initialization
→ V5 root creation and confirmation
→ Core-only M5 episode binding through V5 boundary
→ confirmed ScriptVersion
→ EpisodeProductionRun(ROOTS_READY)
→ restart + read-only lineage verification
→ secret-free receipt and database inventory
→ atomic canonical-directory publication
→ authenticated Creator Public API read verification
→ STOP at M6/Identity/rights/provider gates
```

## Rejected alternatives

- **Reuse test refs or test seed helpers:** rejected because tests are not authority.
- **Direct SQL or SQLite copy/edit:** rejected because it bypasses V5 validation and
  lifecycle integrity.
- **Start Creator on its default path and fill the empty database later:** rejected
  because the location is implicit and partial initialization is easy to misstate.
- **Add a public M5 binding route solely for bootstrap:** rejected because the
  accepted external HTTP contract does not expose this Core-only operation.
- **Attach historical runtime evidence to the new run automatically:** rejected
  because the historical evidence was not produced under the new run lineage.

## Exit state

The bounded bootstrap checkpoint may report only:

```text
K2_CANONICAL_ROOT_STATUS=ROOTS_READY
M6_AUTHORITY_STATUS=NOT_CREATED
IDENTITY_LOCK_STATUS=NOT_CREATED
P1_GATE=NOT_PASSED
PUBLICATION_ALLOWED=false
```

It may not report `FEATURE ACCEPTED`, P1 pass, production readiness or publication
eligibility.
