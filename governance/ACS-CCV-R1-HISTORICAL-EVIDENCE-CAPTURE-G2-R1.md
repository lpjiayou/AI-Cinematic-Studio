## 3. Authorized recovery

G2-R1 may perform one bounded repeat source-read-only collection using the G1
finalizer and frozen registers. It may:

- read and hash only explicitly registered historical source paths;
- copy positive-size source bytes into a new repository-external custody root;
- recover or explicitly mark unavailable the exact 27 non-output records;
- copy or explicitly mark unavailable all 50 frozen historical outputs and exact
  per-run seeds;
- preserve model bytes behind every model digest;
- produce two independently generated byte inventories and a collection receipt;
- normalize the capture offline through the G1 finalizer;
- package the custody into integrity-addressed archives for persistent storage.

The recovery must retain explicit `MISSING`, `AMBIGUOUS`, usage-unverified,
license-unverified, lineage-incomplete and failure-evidence gaps. Narrative memory
must not fill a missing fact.

## 4. Source protection

Historical source paths are read-only. The collector must not:

- start ComfyUI, a worker, a model server or a generation script;
- generate, regenerate, repair, convert, crop, rename, touch, chmod or rewrite a
  historical source file;
- install or upgrade a dependency, model or node;
- infer or recreate a seed, workflow, log, failure event, usage link or license;
- follow a symlink outside an explicitly confined source or custody root;
- add a raw evidence byte, generated image, model or credential to Git;
- disclose provider tokens, private keys, credentials or unsanitized logs in chat.

If source and destination separation cannot be proven, collection stops.

## 5. Persistence gate

The first G2 custody loss establishes an additional mandatory gate. Before the GPU
host may be released, G2-R1 must prove all of the following:

1. `source-inventory.json` and `custody-copy-inventory.json` agree on every copied
   path, size and SHA-256;
2. the G1 finalizer completes without GPU execution and preserves a partial status
   whenever evidence remains missing or ambiguous;
3. a post-finalizer custody rehash passes against the frozen inventory;
4. the evidence root is archived in deterministic, size-bounded volumes with a
   separate SHA-256 index;
5. at least one copy is transferred outside the active compute instance;
6. the provider data is saved for reuse without release or deletion;
7. a later instance reattaches the saved data and repeats the archive/index and
   custody verification successfully.

A provider control-panel `保存完成` label alone is not sufficient. The bytes and
their digest index must be readable after reattachment.

## 8. Independent-review and CCV-R2 transition

G2-R1 completion does not itself accept the evidence. An independent review must
read the sanitized JSON package, verify the custody/archive indices against retained
bytes and confirm the frozen 27-record/50-run boundary.

Only an independent-review `PASS` conditionally activates `CCV-R2-G0`, limited to:

- governance;
- reproducible experiment design;
- frozen samples, seeds, workflows, metrics, blind review and failure ledger;
- no product schema implementation;
- no GPU execution;
- no M6/M8/M10 production implementation.

Any `REVISION REQUIRED`, missing retained byte, digest mismatch, unavailable archive
or failed reattach keeps `CCV-R2-G0` inactive.
