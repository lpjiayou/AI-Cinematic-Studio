# AI Cinematic Studio 架构决策记录模板

> 使用说明：复制本文件创建一份独立 ADR，完整填写所有“必填”字段后发起架构评审。ADR 用于记录已识别的架构问题与决策，不得用于绕过审批、预先实现未来模块或修改未经授权的 V2.3 架构。

## 文档元数据

| 字段 | 填写内容 |
| --- | --- |
| ADR ID（必填） | `ADR-XXXX`，使用仓库内唯一、连续且不可复用的编号 |
| Title（必填） | 用一句话描述决策主题 |
| Status（必填） | `Proposed` / `Accepted` / `Rejected` / `Superseded` / `Deprecated` |
| 作者 | 姓名或团队标识 |
| 创建日期 | `YYYY-MM-DD` |
| 最后更新日期 | `YYYY-MM-DD` |
| 审批人 | 项目负责人、架构责任人及必要的专项责任人 |
| 关联事项 | 任务、风险、接口契约或其他 ADR 的可追溯引用；无则写“无” |
| Supersedes | 被本 ADR 替代的 ADR ID；无则写“无” |
| Superseded by | 替代本 ADR 的 ADR ID；无则写“无” |

## ADR ID

`ADR-XXXX`

编号一经分配不得修改或复用。被拒绝、废弃或替代的 ADR 仍保留原编号和历史记录。

## Title

`<以决策为中心的简洁标题>`

标题应描述要解决的架构决策，不写实现任务清单。

## Status

`Proposed`

状态含义：

- `Proposed`：已提交，尚未获得实施授权。
- `Accepted`：已由规定审批人批准，可按决策范围实施。
- `Rejected`：已评审但未采纳，仅保留审计记录。
- `Superseded`：已被另一份 Accepted ADR 明确替代。
- `Deprecated`：不再推荐采用，但可能仍处于受控迁移期。

只有 `Accepted` 状态构成实施授权。修改状态时必须记录审批人与日期。

## Context

<!-- 必填 -->

描述需要决策的问题和约束，至少包括：

- 当前可验证事实与问题触发原因。
- 适用范围和明确不在范围内的事项。
- 必须保持不变的 V2.3 架构约束。
- 相关质量属性、合规要求和治理限制。
- 已知假设、依赖和不确定性。

不得将提案、推测或未来设想写成当前架构事实。

## Decision

<!-- 必填 -->

清楚记录最终选择：

- 决定采用什么，以及为什么。
- 决策适用的边界、前置条件和生效时间。
- 允许的行为与明确禁止的行为。
- 验证决策得到正确执行的方式。
- 决策责任人和后续复核条件。

决策内容必须与审批范围完全一致；审批后不得通过实现扩大范围。

## Migration Plan

<!-- 必填；无迁移时写“无迁移”，并说明为何不存在存量影响 -->

迁移计划至少包括：

1. 前置条件与依赖。
2. 分阶段实施步骤与每步完成判据。
3. 兼容策略及存量资产处置方式。
4. 验证、监控与回滚条件。
5. 责任人、目标时间及沟通对象。
6. 旧设计停止使用和文档归档的时点。

## Phase 0 使用边界

Phase 0 中，ADR 只能记录和保护工程基础决策，不能授权业务代码、业务功能、服务实现、数据库表或持久化设计，不能引入大型依赖，也不能改变 V2.3 架构。超出此边界的内容必须等待后续阶段获得明确授权。
