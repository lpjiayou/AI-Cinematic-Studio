# 层级边界

## 1. 目的

本文件定义仓库顶层区域的最小职责边界，防止未获批实现、循环依赖和职责漂移。规则只覆盖仓库级工程边界，不推导未来业务模块。

## 2. 顶层边界

| 路径 | 允许内容 | 禁止内容 |
| --- | --- | --- |
| `apps/` | 获批应用的入口、装配与应用专属适配 | 可复用核心能力、跨应用共享实现、基础设施资源定义 |
| `services/` | 获批独立服务的入口、用例编排与公开契约实现 | 其他服务内部实现、前端应用代码、部署平台脚本 |
| `packages/` | 经至少两个消费者或明确平台契约验证的共享能力 | 应用专属流程、服务私有逻辑、为了“可能复用”而提前抽象的代码 |
| `infrastructure/` | 环境、构建、部署、资源和策略的声明性配置 | 产品业务规则、业务数据模型、共享运行时捷径 |
| `tests/` | 单元、集成、契约、端到端测试及其测试资产 | 生产运行时代码、真实机密、无法追溯来源的生产数据 |
| `scripts/` | 构建、检查、发布、迁移辅助等可重复工程操作 | 业务决策、长期运行服务、绕过正式入口的生产逻辑 |
| `docs/` | 按主题归档的说明、决策背景和操作知识 | 凭据、未脱敏数据、与强制基线冲突且未标注状态的规则 |
| `architecture/` | 当前有效的跨仓库架构基线 | 单一功能的实现细节、未经批准的未来模块设计 |
| `governance/` | 强制开发和协作规则 | 业务需求、技术实现代码、一次性会议记录 |

## 3. 测试边界

| 目录 | 验证范围 | 典型依赖限制 |
| --- | --- | --- |
| `tests/unit/` | 单一单元的确定性行为 | 不访问真实网络、外部服务或持久化资源 |
| `tests/integration/` | 两个或以上真实技术组件的协作 | 外部依赖必须可隔离、可重建 |
| `tests/contract/` | 跨边界公开契约的兼容性 | 只依赖已发布/声明的契约，不依赖对方内部实现 |
| `tests/e2e/` | 获批关键路径的系统级行为 | 使用受控环境与测试数据，不持有生产机密 |

Phase 0 只建立这些位置，不创建测试代码或测试技术栈。

## 4. 文档边界

根目录 `architecture/` 和 `governance/` 保存当前有效、跨仓库强制执行的基线；`docs/` 保存按主题组织的详细知识。重复内容应通过链接引用，避免出现两个无法判断优先级的规则源。

若专题文档与强制基线冲突，合并前必须更新强制基线或明确记录例外；不得通过在 `docs/` 中增加一份相反说明来绕过规则。

## 5. 边界变更条件

新增顶层目录、改变目录职责或允许新的跨层依赖，至少需要：

1. 关联明确的工程任务与变更动机；
2. 说明受影响的生产者、消费者和迁移路径；
3. 更新责任矩阵与依赖规则；
4. 通过架构守卫要求的评审；
5. 确认不擅自改变 V2.3 已批准的未来模块架构。
